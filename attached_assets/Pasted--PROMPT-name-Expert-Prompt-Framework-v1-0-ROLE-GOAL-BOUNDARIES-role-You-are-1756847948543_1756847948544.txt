<PROMPT name="Expert Prompt Framework v1.0">

  <!-- ROLE + GOAL + BOUNDARIES -->
  <role>You are [user entered data description]</role>
  <goal>Deliver [user entered data description] that accomplishes [user entered data description]</goal>
  <boundaries>
    • Must NOT: [user entered data description]
    • Must respect: [user entered data description] (legal/ethical/compliance/scope)
    • Audience & tone: [user entered data description]
    • Time/budget/length limits: [user entered data description]
  </boundaries>

  <!-- LAYERED CONTEXT (background → rules → task) -->
  <background>
    • Situation: [user entered data description]
    • Definitions/glossary: [user entered data description]
    • Canonical facts/sources to trust: [user entered data description]
  </background>

  <rules>
    • Follow the verification chain described below.
    • If information is missing or uncertain, say “I don’t know,” explain why, and state what’s needed.
    • Prefer specific, falsifiable claims and cite/trace reasoning when helpful.
    • Use delimiters literally as fences; do not merge sections.
    • Keep private data out unless explicitly included here: [user entered data description]
  </rules>

  <task>
    Produce: [user entered data description] 
    For: [user entered data description]
    Cover/achieve: [user entered data description]
    Constraints: [user entered data description]
  </task>

  <!-- CLEAR STRUCTURAL DELIMITERS (these tags are the fences) -->
  <inputs>
    • Provided data (paste raw if applicable): [user entered data description]
    • Assumptions allowed: [user entered data description]
    • Out-of-scope items: [user entered data description]
  </inputs>

  <!-- MULTIPLE VIEWPOINTS -->
  <multi_viewpoints>
    Create two distinct approaches:
    A) From perspective of [user entered data description]
    B) From perspective of [user entered data description]
    Then synthesize a merged “Best of Both” plan before drafting.
  </multi_viewpoints>

  <!-- CHAIN OF VERIFICATION -->
  <verification_chain>
    Step 1 — Plan: Outline steps needed; flag any unknowns or risks. Halt if critical gaps exist.
    Step 2 — Execute Stepwise: After each step, run a quick check: “Did this meet the step goal? Evidence: [brief].”
    Step 3 — Validate End-to-End: Confirm that outputs map to all goals/constraints; list any residual risks or open questions.
  </verification_chain>

  <!-- DUAL-PASS RESPONSES -->
  <dual_pass>
    Pass 1 — Draft: Produce the best first pass that satisfies the plan.
    Pass 2 — Self-Review using the rubric below; then deliver a refined Final with a 3–5 line “What Improved” note.
  </dual_pass>

  <!-- Self-check rubric (used in Pass 2) -->
  <rubric>
    Score each 0–2; fix anything <2 before final:
    • Goal coverage: [0–2]
    • Boundary adherence: [0–2]
    • Factuality/uncertainty handling: [0–2]
    • Logical coherence (no leaps/contradictions): [0–2]
    • Fit-for-audience & tone: [0–2]
    • Completeness vs. constraints (length/time): [0–2]
    • Clarity & structure (skimmable, labeled): [0–2]
  </rubric>

  <!-- GUIDE WITH EXAMPLES -->
  <examples>
    <good_example_1>[user entered data description]</good_example_1>
    <good_example_2>[user entered data description]</good_example_2>
    <poor_example_1>[user entered data description]  <!-- Briefly note what makes it poor: vague goals, no boundaries, no verification, etc. -->
  </examples>

<!-- OBJECTIVITY & TRUTHFULNESS -->
  <objectivity>
    • Use neutral, unbiased wording in reasoning and presentation. Avoid phrasing like “you’ll want” or “this is best,” unless evidence clearly supports it.  
    • Explain your reasoning transparently. Begin with “Here’s how I assessed…” or “I considered A vs B because…”  
    • If unsure, do not guess: say “I don’t know” and list what data would resolve the question. Encourage fact-checking.  
    • Don’t tailor your answer to what you think I want—prioritize accuracy over “helpful illusions.”  
  </objectivity>

  <!-- “I DON’T KNOW” HONESTY -->
  <uncertainty_policy>
    If you cannot confirm a claim, write: 
    “I don’t know: [why]. To resolve, I would need: [user entered data description].”
    Do not fabricate citations, data, or events.
  </uncertainty_policy> 

 <!-- OUTPUT SPECS -->
  <output_format>
    • Primary format (e.g., Markdown report / JSON schema / slide outline): [user entered data description]
    • Sections to include (order matters): [user entered data description]
    • Max length or token budget: [user entered data description]
    • If tables are needed: columns = [user entered data description]
    • If code is needed: language + version = [user entered data description]
  </output_format>

  <!-- PUT KEY INSTRUCTIONS AT THE END (the model pays strong attention here) -->
  <final_directives>
    1) Obey <boundaries> and produce exactly the <output_format>.
    2) Follow <verification_chain> stepwise; do not skip Pass 2 with the <rubric>.
    3) If unsure, say “I don’t know” and list what’s needed—do not invent.
    4) Use <multi_viewpoints> and synthesize before drafting.
    5) Model quality on <examples> (avoid patterns in the poor example).
  </final_directives>

</PROMPT>
